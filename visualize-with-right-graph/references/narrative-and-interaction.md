# 阅读顺序、交互与实现

## 根据用途分配控制权（R05）

| 目的 | 默认视图 | 增加复杂度的条件 |
| --- | --- | --- |
| 探索 | 中性问题、总体分布和范围 | 未知目标需要按组找、回总览或追溯时，提供开放探索 |
| 解释 | 一幅有重点的图、证据顺序和必要背景 | 单图无法容纳证据链时，用对齐小图或分步。先引导后探索适合读者既要理解又要核对自己的子集 |
| 监控 | 当前值、阈值、最近完整更新、异常 | 只有异常需要诊断时，提供历史和明细入口 |
| 决策 | 并列选项、同口径指标、约束及不确定性 | 可解释的输入会改变选择时，加情景切换。区分观察数据和情景模型 |
| 比较与诊断 | 共同基准、当前比较对象和差异 | 需要找异常的来源时，增加子组、明细或证据分层 |

有叙事价值时，按读者问题、背景、证据、差异、限制和行动含义组织。单图能解决时，静态注释往往足够。多步骤各有独立问题时可用可跳转幻灯片或分步展示，显示位置并可前后切换。案例可借鉴 [证据账本](sources.md) 中 Gapminder 的分节导航。优先测试静态或无动画路径。

标题由证据定。事实确定时写结论及范围；探索中用问题或描述；筛选后固定论断若已失效，改成当前切片的描述。用直接标签、紧邻注释、排序、对齐和留白形成阅读顺序。颜色只强调有意义的差异，同类状态跨图同色，类别再加文本或形状；连续强度按有序尺度。当前范围与基准范围完全相同时，可合并重复摘要，切到子集后再显示基准与差值。对齐可比较的轴与基准，独立尺度显式标识。手机纵向堆叠时保留比较关系，静态导出时在图内显示范围、单位和证据限制。

## 交互合同（R06、R07、R11）

只有能回答新增问题或明显降低读者操作成本时才加控件。采用 Yi 等人的意图分类来问“读者要完成什么”，再选控件。

| 意图 | 使用条件 | 可能的控件 |
| --- | --- | --- |
| Select | 保持某对象可追踪 | 持久选择与清除 |
| Explore | 到别的时间段或局部查看 | 平移、缩放、时间范围 |
| Reconfigure | 改变排序或组织方式以比较 | 按指标排序、调整分组 |
| Encode | 同一数据需要另一种视觉读法 | 可理解的编码切换 |
| Abstract/Elaborate | 看不同聚合级别或单个观测 | 粒度、详情面板 |
| Filter | 明确选择满足条件的子集 | 分组、日期或阈值控件 |
| Connect | 在相关视图或明细中找同一对象 | 联动高亮、关联明细 |

为每个控件保留一条简短合同：

> 读者问题 → 可发现的标签与触发方式 → 状态与受影响视图 → 当前状态提示 → 清除/重置 → 空、缺失或失败状态 → 触屏、键盘、静态导出对应方式。

- **选择与筛选。** 高亮只改变焦点时，总体与分母保持并明示。筛选改变范围时，标题、分子分母、n、单位、摘要、注释、图、表和导出共用同一派生结果；固定分母的指标另标。过滤后选中对象消失时清除选择或显示原因。真实零保留，空集和无定义率单列。
- **必要信息可见。** 悬浮可补信息；必须查的精确值或关键证据要能由标签、可操作详情或表获得。键盘与触屏都能触发、读状态和清除。保留可见焦点和逻辑顺序。拖动有简单替代，长表提供合理导航。颜色以外保留识别线索。
- **过渡与错误。** 仅在动画解释对象连续性或状态变化时使用，支持减弱动态效果。数据请求显示加载、无结果或失败，保留恢复路径。异步筛选防止旧响应覆盖新状态。
- **导出。** 明确导出当前切片或固定总览；图内保留范围、n、分母和缺失口径。静态交付若要让读者比较多个状态，给代表状态并列或可查明细。

## 把设计变成可用产物（R09、R12）

1. **先看环境。** 用户要求的文件格式、框架、依赖、离线要求和访问条件优先。互动宿主只存在于当前环境时，明确产物能否下载或转交。当前环境无法实现时，交付可运行的降级方案或规格，并标出缺的能力。
2. **按复杂度实现。** 小数据的交互页可用单文件 HTML、原生控件和 SVG，加表格供精确读取。已有应用优先复用它的组件和数据接口。复杂联动、地图投影或大数据按已安装能力采用图表库、专门工具、Canvas/WebGL 或服务端聚合；检查库版本、数据规模、可访问替代和离线加载。静态报告选目标介质可嵌入的 SVG、PNG 或 PDF。
3. **让状态可复查。** 保留原始数据，先解析单位和缺失；将视图状态、变换和绘制分开。推荐数据流：原始记录 → 业务口径 → 当前筛选 → 派生值 → 同步渲染图、摘要、表和导出。通过稳定 ID 联动。用明确的空值分支。注入外来标签时按文本处理；嵌入数据时安全转义，离线产物尽量不依赖远程资源。避免把无授权的原始明细嵌入可转交产物。
4. **记录实际验证。** 在真实目标尺寸看默认、最密和空结果；走一遍键盘或触屏路径，核对重置和导出。记录“设计适合、工具可实现、实际运行通过”各自的证据。组件文档只证明公开能力，用户的图仍需自己运行验证。
