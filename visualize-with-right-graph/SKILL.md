# Visualize With the Right Graph

让目标读者在实际交付环境中正确回答关键问题。先确定比较对象和证据，再选图。一个数、表格、暂缓制图也可以完成任务。

## 工作流

1. **理解。** 用一句话写下“谁在什么场景下，用什么数据回答什么问题”。把成功写成读者能完成的任务。快速请求直接做。只有不确定性会改变结论、口径或主要设计时，才问最少的问题；可逆选择写明假设后继续。
2. **审数据。** 确认对象、观测粒度、单位、窗口、分母、覆盖、配对、缺失和可比性。区分事实、推断和未知。数据不能回答问题时，说明缺口，交付可支持的部分。示例数据在产物内显式标注。
3. **选表达。** 把业务问题转成查值、比较、找变化、识别异常等操作。决定用数值、表格、单图、组合视图、叙事序列或交互探索。精确比较优先共轴位置或直接数值；长度编码要有有意义的基线。遵守明确的图表、格式和技术要求；若有明显缺陷，说明影响并提供替代选项。若请求的含义无法由数据真实表达，交付可支持的部分并指出缺字段。
4. **设计和实现。** 先做好默认视图，再为明确的分析问题增加交互。用有证据的标题、排序、对齐和少量注释组织视线。按环境选择实现，区分“设计适合”“工具支持”“已运行验证”。复杂任务可比较两三种候选，按任务覆盖、误读、读者成本和实现代价取舍。
5. **验证和修订。** 复算关键值，在目标尺寸渲染，实际走关键交互路径。对照预设读者问题检查任务适配。记录通过、失败、未执行或不适用，并回到最早出错的环节修订。模型自检和浏览器运行均不能替代真实读者测试。

交付产物、主要发现或用途，以及影响理解的假设和限制。复杂任务保留可复查的口径、变换、设计和验收记录，按需展示。
