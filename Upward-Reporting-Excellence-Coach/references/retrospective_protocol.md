# 复盘闭环协议

本文档定义upward-reporting-coach-v2技能的复盘闭环机制，包括反馈收集、信息提取、档案存储和自适应调用规范。

---

## 复盘闭环的价值主张

向上汇报是一个持续迭代的技能。每次汇报结束后，领导的反馈都是宝贵的学习信号——它告诉你：
- 这位领导真正关心什么
- 你的表达方式哪里打动了他、哪里没说清楚
- 下次汇报应该调整什么

复盘闭环机制将"一次性工具"升级为"成长型陪伴"：每次汇报的经验都会沉淀下来，让下一次汇报更精准、更高效。

---

## 轻量版交互设计

**设计原则：**
用户汇报结束后通常很累，不应要求填写复杂的问卷或表单。采用"一句话反馈"机制——用户只需用自然语言描述汇报过程，技能自动提取结构化信息。

**典型交互示例：**

**用户（汇报后）：** "刚才汇报完了，老板主要关注成本，对进度没啥意见，但问了好几个关于人力投入的细节问题。"

**技能响应：** 
```
✅ 复盘反馈已记录到你的个人汇报档案。

📊 本次反馈摘要：
   - 领导关注点：成本控制、人力投入细节
   - 领导满意部分：进度把控
   - 领导追问方向：人力投入的细节论证
   
💡 下次建议：
   - 成本相关模块增加数据颗粒度
   - 提前准备人力ROI的支撑数据
   - 这位领导偏好"细节型"风格，未来汇报话术会自动调整
   
🎯 你已完成{{N}}次汇报复盘，持续积累中。
```

## 信息提取规则

从用户的一句话反馈中，自动提取以下结构化字段：

### 必提取字段

| 字段 | 说明 | 提取方法 |
|------|------|---------|
| 汇报日期 | 本次汇报的日期 | 默认为当天，除非用户明确说"昨天"等 |
| 汇报场景 | 常规/项目/总结/问题升级/方案决策 | 根据本次使用技能时的场景识别结果 |
| 汇报对象 | 向哪位领导汇报 | 用户提到的领导姓名/职位，如未提及则标记为"未记录" |

### 核心提取字段

| 字段 | 说明 | 提取方法 |
|------|------|---------|
| 领导关注点 | 领导主要关心什么 | 提取关键词：成本/进度/风险/人力/数据/效果/团队等 |
| 领导满意部分 | 哪些地方得到认可 | 识别正向反馈信号："没问题"、"不错"、"继续保持"、"认可"等 |
| 领导质疑部分 | 哪些地方被追问或质疑 | 识别追问信号："问了好几个"、"不太认可"、"觉得XX不够"等 |
| 领导决策结果 | 做出了什么决策（如适用） | 提取决策信号："同意"、"批准"、"再研究"、"暂缓"等 |

### 风格标签提取

根据反馈内容推断领导的沟通风格，打上标签（可多选）：

**维度1：信息颗粒度偏好**
- `细节型`：追问具体数字、实现细节、操作步骤
- `全局型`：更关心战略意义、整体影响、长期价值

**维度2：论证方式偏好**
- `数据驱动型`：要求数据支撑、量化指标、对比分析
- `故事驱动型`：对案例、场景、用户故事更感兴趣

**维度3：决策风格**
- `决断型`：当场拍板、明确表态
- `探讨型`：倾向于多问几个问题、要求更多信息再决策

**维度4：风险偏好**
- `风险敏感型`：频繁追问风险、Plan B、异常情况
- `收益导向型`：更关心价值、机会、增长空间

**提取方法：**
根据"领导关注点"和"领导质疑部分"的内容特征，匹配对应标签。如果单次反馈信息不足，标记为"待补充"，等多次反馈后再确认。

## 档案存储格式

复盘档案存储在用户级working memory：`~/.workbuddy/memory/reporting_history.md`

### 文件结构

```markdown
# 个人汇报档案

本文件记录历次向上汇报的复盘反馈，供upward-reporting-coach-v2技能自动读取并优化未来汇报话术。

---

## 2026-04-17 | 项目进展汇报 | 向张三领导

**汇报场景：** 项目汇报  
**领导关注点：** 成本控制、人力投入细节  
**领导满意部分：** 进度把控  
**领导质疑部分：** 人力投入是否过高、ROI论证不充分  
**领导决策结果：** 同意继续推进，要求下次汇报时补充人力ROI数据  
**领导风格标签：** 细节型、数据驱动型、风险敏感型  
**下次建议：** 成本模块增加数据颗粒度、提前准备人力ROI支撑数据、风险部分主动预埋Plan B  

**原始反馈：** "刚才汇报完了，老板主要关注成本，对进度没啥意见，但问了好几个关于人力投入的细节问题。"

---

## 2026-03-25 | 季度总结汇报 | 向李四领导

**汇报场景：** 总结汇报  
**领导关注点：** 业务价值、可复用性  
**领导满意部分：** 数据呈现清晰、成果亮点突出  
**领导质疑部分：** 对其他团队的影响未提及  
**领导决策结果：** 认可成果，建议推广到其他部门  
**领导风格标签：** 全局型、收益导向型、决断型  
**下次建议：** 强化全局视角、主动讲述跨团队影响、准备可复用方案  

**原始反馈：** "李总对数据很满意，但他问了一句'对其他团队有什么启发'，我当时没准备，有点懵。最后他说可以推广。"

## 领导风格档案

基于多次汇报反馈，沉淀的领导风格画像：

### 张三（直属领导）

- **确认标签：** 细节型、数据驱动型、风险敏感型
- **汇报次数：** 3次
- **高频关注点：** 成本、人力、风险、数据来源
- **典型追问：** "这个数字怎么来的？"、"如果XX出问题怎么办？"
- **汇报策略：** 数据要细、风险要提前讲、备好Plan B

### 李四（上级领导）

- **确认标签：** 全局型、收益导向型、决断型
- **汇报次数：** 2次
- **高频关注点：** 业务价值、跨团队影响、可复用性
- **典型追问：** "对公司整体有什么意义？"、"能不能推广？"
- **汇报策略：** 强调战略价值、主动讲全局影响、准备复用方案

---

*本文件由upward-reporting-coach-v2自动维护。最后更新：2026-04-17*
```

### 存储规则

**新增记录：**
- 每次复盘后，在文件顶部追加新记录（最新的在最上面）
- 使用二级标题格式：`## 日期 | 场景 | 向XX领导`
- 保留用户的原始反馈原文（便于后续回溯）

**领导风格档案更新：**
- 当同一位领导积累3次及以上反馈后，在"领导风格档案"区域创建或更新该领导的画像
- 风格标签需至少2次反馈一致才标记为"确认标签"
- 汇报策略基于高频关注点和典型追问总结

**文件大小管理：**
- 当记录超过30条时，将12个月前的旧记录归档到`reporting_history_archive_YYYY.md`
- 保留最近30条记录和所有"领导风格档案"

## 下次调用时的自适应逻辑

当用户下次使用技能生成汇报话术时，执行以下自适应流程：

### 步骤1：档案读取

读取`~/.workbuddy/memory/reporting_history.md`，提取：
- 最近3次汇报的反馈（了解用户的总体习惯）
- 针对本次汇报对象的所有历史记录（如果汇报对象在档案中）

### 步骤2：场景匹配

判断本次汇报对象是否在档案中：
- **如果在**：读取该领导的风格标签、高频关注点、典型追问、汇报策略
- **如果不在**：仅参考用户的总体汇报习惯（如用户倾向于数据密集型话术还是故事型话术）

### 步骤3：话术生成调整

根据领导风格标签，在话术生成阶段应用以下调整策略：

| 风格标签 | 话术调整策略 |
|---------|------------|
| 细节型 | 增加数据颗粒度、补充实现细节、准备数据来源说明 |
| 全局型 | 强化战略意义表达、弱化执行细节、增加"对整体的影响"模块 |
| 数据驱动型 | 每个结论都配对比数据、增加图表可视化建议、准备数据来源备查 |
| 故事驱动型 | 用具体案例包装数据、增加场景化描述、讲"用户怎么说" |
| 决断型 | 明确提出需要决策的事项、提供清晰的选项对比 |
| 探讨型 | 预留讨论空间、准备多版本方案、不要过早收口结论 |
| 风险敏感型 | 主动在话术中预埋风险说明和Plan B、补充异常情况应对 |
| 收益导向型 | 强化价值和机会表达、弱化风险叙述（但不回避） |

### 步骤4：问答预判增强

如果该领导在档案中有"典型追问"记录，在五维问答预判环节：
- 优先列出该领导历史上问过的类似问题
- 针对高频关注点设计问答预案
- 标注："基于历史记录，这位领导可能会问XX"

### 步骤5：向用户透明化反馈

在话术交付时，明确告诉用户技能做了哪些自适应调整：

```
💡 基于你的汇报档案，本次话术已自动优化：
   
   针对{{领导姓名}}的风格（{{风格标签}}），我做了这些调整：
   - {{调整1}}
   - {{调整2}}
   - {{调整3}}
   
   如果你觉得这些调整不合适，告诉我，我可以按标准版重新生成。
```

## 复盘提醒机制

### 主动提醒时机

在第一阶段核心话术交付完成时，主动嵌入复盘提醒：

```
📌 汇报现场备忘卡已生成完毕。

💡 小提示：汇报结束后，花30秒告诉我"领导主要关注了什么、对哪些点有疑虑"，
   我会把这次反馈存入你的个人汇报档案，下次生成话术时自动参考领导偏好，
   让每一次汇报都比上一次更精准。
   
   随时回来找我复盘，一句话就够。
```

### 不主动催促

如果用户汇报后没有回来复盘，**不要**通过其他渠道（如定时消息）催促。保持轻量级原则——复盘是增值服务，不应成为用户负担。

### 可选的定时提醒（需用户主动开启）

如果用户表示"担心忘记复盘"，可提供自动提醒选项：

```
如果你担心汇报后忘记复盘，我可以帮你设置一个提醒：
在你预定的汇报时间后2小时，自动推送一条消息提醒你复盘。
需要设置吗？（需要提供汇报时间）
```

如用户同意，调用automation机制创建一次性提醒任务。

## 质量保障机制

### 提取准确性校验

在信息提取完成后，向用户展示提取结果，并询问确认：

```
✅ 复盘反馈已记录。以下是我提取的关键信息，请确认是否准确：

📊 本次反馈摘要：
   - 领导关注点：成本控制、人力投入细节
   - 领导满意部分：进度把控
   - 领导追问方向：人力投入的细节论证
   
如果有误或遗漏，请补充说明，我会更新档案。
```

用户可以直接回复"没问题"或"漏了XX"来确认或修正。

### 风格标签确认机制

当同一位领导的风格标签首次确认（达到3次反馈一致）时，主动向用户确认：

```
📊 基于你的3次汇报反馈，我判断张三领导的风格为：
   细节型、数据驱动型、风险敏感型
   
   这个判断准确吗？如果准确，下次向他汇报时，我会自动调整话术策略。
   如果不准确或需要补充，请告诉我。
```

### 档案隐私保护

`reporting_history.md`存储在用户本地working memory，不上传到任何服务器。用户可以随时：
- 查看档案内容（技能提供"查看我的汇报档案"指令）
- 删除特定记录（技能提供"删除XX日期的汇报记录"指令）
- 清空全部档案（技能提供"清空汇报档案"指令，需二次确认）

## 技术实现注意事项

### 文件读写
- 首次使用时，如`reporting_history.md`不存在，自动创建文件和目录结构
- 每次追加记录使用`replace_in_file`工具，先读取文件内容，再在顶部插入新记录
- 更新"领导风格档案"区域使用精确字符串替换，避免误改其他记录

### 信息提取
- 使用LLM的理解能力从用户的一句话反馈中提取结构化字段
- 如果用户反馈过于简略（如只说"还行"），主动追问："能具体说说领导关注了什么吗？"
- 如果用户明确说"没啥好说的"或"领导没反馈"，记录为"本次无有效反馈"，不强求

### 风格标签推断
- 风格标签推断基于语义理解，不要求用户使用特定关键词
- 例如："他问了好几个关于成本的细节"→推断为"细节型"+"成本关注"
- 单次反馈信息不足时，标签标记为"待补充"，避免误判

### 自适应调用
- 下次调用时，先判断`reporting_history.md`是否存在，不存在则跳过自适应逻辑
- 读取档案后，匹配"汇报对象"字段识别是否有历史记录
- 如果用户未提及汇报对象（如只说"帮我准备汇报"），询问："这次是向谁汇报？如果是档案里记录过的领导，我可以参考历史偏好优化话术。"
