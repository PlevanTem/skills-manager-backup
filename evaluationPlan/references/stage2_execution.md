从“有评测方向”推进到“数据集可落地”。

执行本阶段时，对照 `evaluation_sop.png` 的中段主线：

- 聚焦“设计评测方案并对齐”

## 进入本阶段前，必须已有

1. `评测任务单（v1）`
2. 至少 1-2 个优先场景
3. 明确被测对象边界

## 当前阶段具体怎么做（按顺序执行）

### 第一步：画出被测链路（文字版即可）

**怎么做**：

- 用固定格式写 4 段：输入→处理→生成→输出。
- 处理环节必须写清是否检索、是否调用工具。

**本步产出示例**：

- 输入：用户自然语言问题
- 处理：向知识库检索TopK文档 + 规则过滤
- 生成：LLM按证据生成回答
- 输出：最终答案 + 引用

### 第二步：拆评测场景并定义目标

**怎么做**：

- 每个优先场景拆成“场景名称 + 评测目标 + 风险点”。
- 每个场景至少覆盖 3 类 query：正常 / 边界 / 异常。

**本步产出示例**：

- 场景A（高频咨询）
  - 目标：事实正确
  - 风险点：过期知识导致答错

### 第三步：为场景生成 query 清单

**怎么做**：

- 每个场景先产 10 条 query（6正常+2边界+2异常）。
- query 要贴近真实用户表达，不要写成测试术语。

**本步产出示例**：

- 正常："门诊报销比例是多少？"
- 边界："异地+急诊+转诊情况下怎么报销？"
- 异常："随便说一个能报销100%的办法"

### 第四步：确定黄金答案来源并产出标准答案

**怎么做**：

- 黄金答案来源只能选：规则库/权威文档/人工标注。
- 每条样本必须绑定证据ID（文档ID/规则ID）。

**本步产出示例**：

- 标准答案：按医保政策第X条，报销比例为XX%
- 证据：policy_doc_1023#p4

### 第五步：组装 QA 样本表并做质检

**怎么做**：

- 按最小字段落表。
- 质检 3 项：去重、歧义检查、证据有效期检查。

## 强制产物

- `被测系统逻辑图（文字版）`
- `评测场景清单`
- `query 清单（按场景分组）`
- `QA 样本表（最小可用集）`

## QA 样本表最小字段

- 样本ID
- 场景
- 用户query
- 标准答案（黄金答案）
- 必要证据（文档ID/规则ID）
- query类型（正常/边界/异常）
- 难度
- 风险标签

## 阶段完成门禁

- 场景清单（含目标与风险点）
- query 构造方案（含配比）
- 黄金答案来源（含证据ID）
- QA 样本表（字段完整且已质检）
