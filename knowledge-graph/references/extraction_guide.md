# 实体关系提取规则

SKILL.md 已内联常用判定规则。本文件仅在以下场景查阅：
- 遇到复杂的实体 vs 属性判定
- 隐含关系识别不确定
- 需要完整的信号词参考表

---

## 提取流水线（三段式）

将原来的九阶段合并为三段并行流水线，减少串行等待：

```
┌─ 段A：识别 ──────────────────────┐
│  实体识别 + 属性提取 + 类型判定    │  ← 可并行处理多段文档
├─ 段B：关联 ──────────────────────┤
│  关系提取 + 术语表 + 代码映射     │  ← 段A产出后立即启动
├─ 段C：规则与流程 ────────────────┤
│  业务规则 + 业务流程              │  ← 与段B并行
└──────────────────────────────────┘
         ↓ 合并 → 去重消歧 → 质量校验
```

---

## 段A：识别

### 实体候选词模式

| 模式 | 示例 | 类型 |
|------|------|------|
| 「XX系统/平台/模块」 | "支付系统" | `core` |
| 「XX记录/单据/申请」 | "退款记录" | `event` |
| 「XX状态/类型/方式」 | "订单状态" | `enum` |
| 「XX信息/资料/详情」 | "银行卡信息" | `attribute` |
| 角色名词 | "商户管理员" | `role` |
| 「XX流程/环节」 | "审核流程" | `process` |

### 实体 vs 属性判定（决策树）

```
名词 N 出现在文本中
  ├─ N 有自己的唯一 ID？ → 是 → 实体
  ├─ N 有独立生命周期？ → 是 → 实体
  ├─ N 被 ≥2 个其他概念引用？ → 是 → 实体
  ├─ N 在代码中有独立的表/类？ → 是 → 实体
  └─ 以上都否 → 属性（挂到最近的实体下）
```

### 属性类型推断

| 文本特征 | 类型 |
|----------|------|
| "XX号/编码/ID" | `string` |
| "金额/价格/费率" | `decimal` |
| "数量/次数" | `int` |
| "是否XX" | `boolean` |
| "XX日期" | `date` |
| "XX时间" | `datetime` |
| 有限选项 | `enum` |

## 段B：关联

### 关系信号词完整表

| 信号词 | 类型 | 方向 |
|--------|------|------|
| "包含/包括/由...组成/下设" | `contains` | 主语→宾语 |
| "属于/隶属于" | `belongs_to` | 主语→宾语 |
| "依赖/基于/需要/前提是" | `depends_on` | 主语→宾语 |
| "关联/对应/绑定" | `associates` | 双向 |
| "是一种/分为" | `generalizes` | 子→父 |
| "触发/引发/导致" | `triggers` | 主语→宾语 |
| "生成/产生/创建/输出" | `produces` | 主语→宾语 |
| "引用/使用/读取/查询" | `references` | 主语→宾语 |
| "管理/维护/审批" | `manages` | 主语→宾语 |
| "转化为/变成" | `transforms` | 主语→宾语 |
| "先于/完成后才能" | `precedes` | 主语→宾语 |
| "限制/约束/必须满足" | `constrains` | 主语→宾语 |

### 隐含关系识别

| 文本模式 | 隐含关系 |
|----------|----------|
| "A 的 B" | A `contains` B |
| "A 中的 B" | A `contains` B |
| "通过 A 进行 B" | B `depends_on` A |
| "A 完成后执行 B" | A `triggers`/`precedes` B |
| "每个 A 有多个 B" | A `contains` B (1:N) |
| 代码中 A 类引用 B 类 | A `references`/`depends_on` B |
| 数据库外键 | 对应业务关系 |

### 术语表构建

从以下来源收集术语，**不需要单独阶段**，在识别实体时顺带完成：

- 实体的 `enName` 和 `synonyms` → 自动生成 glossary 条目
- 属性的 `codeField` / `dbColumn` → 自动生成 glossary 条目
- 文档中出现的英文缩写 → 手动补充

### 代码映射查找策略

有代码仓库时，按以下模式批量全文搜索（一次搜多个关键词）：

```
并行搜索：
  搜索 "class {enName}" → classes
  搜索 "t_{lower_name}" 或 "CREATE TABLE.*{name}" → dbTables
  搜索 "message {enName}" → protoMessages
  搜索 "/v3/{lower_name}" 或 "/{lower_name}" → apis
  搜索 "Create{enName}|Query{enName}|Update{enName}" → functions
```

## 段C：规则与流程

### 规则信号词

| 文本模式 | 类型 |
|----------|------|
| "不能超过/必须/不得/至少/最多" | `validation` |
| "只有...才能/当...时" | `constraint` |
| "等于/=A+B/按照...计算" | `calculation` |
| "有权限/才能操作" | `permission` |
| "先...后.../审批通过后" | `flow_control` |

规则 description 写作三要素：**是什么 + 为什么 + 违反后果**

### 流程识别

文本中出现 "第一步...第二步" / "先...然后...最后" / "A完成后执行B" → 提取为 businessFlow

每步记录：actor + action + entityRef + ruleRef + codeEntry（有代码时）

## 去重与消歧

| 场景 | 处理 |
|------|------|
| 全称=缩写（"商户号"="mchid"） | 保留中文名，变体入 `synonyms` |
| 口语=术语（"店铺"="门店"） | 统一为名词库标准名 |
| 代码名=业务名（`MerchantInfo`="商户"） | 入 `glossary` + `synonyms` |
| 同名异义 | 加限定词拆分，标注「待确认」 |

## 质量校验清单

### 必检（每次都查）

- [ ] 每个 `core` 实体的 description ≥ 2 句话？
- [ ] 无孤立实体（无任何关系）？
- [ ] 关系方向正确？
- [ ] 所有 ID 引用有效（relations/rules/flows 中的 entityRef）？

### 有代码时加检

- [ ] glossary 覆盖代码中的关键变量名？
- [ ] 核心实体有 codeMapping？
- [ ] 有状态的实体记录了 stateTransitions？

## xnoun 名词库批量查询（可选外部接口）

**关键优化**：并行调用，不逐个等待。

```
// 假设名词列表：商户、订单、退款
// 同时发出 3 个等价的外部接口调用：
queryNounDetail(cname="商户")
queryNounDetail(cname="订单")
queryNounDetail(cname="退款")
```

- 有标准定义 → 用名词库定义
- 无结果 → 用文档定义，标 `source: "文档名"`
- 明显通用词（时间/名称/状态）→ 跳过查询
