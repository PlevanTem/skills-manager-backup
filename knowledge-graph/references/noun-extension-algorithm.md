# 名词扩展知识图谱：三信号融合算法

> 被 SKILL.md Stage 2 段D / Stage 3 引用。
> 算法依据：RAGAS OverlapScoreBuilder (高频去噪) + BM25 for KG Construction (Springer 2023) + Amazon MultiImport (多信号融合) + KGTrimmer SIGIR 2024 (度中心性剪枝)。

---

## 适用场景

已有基于领域模型构建的骨架 KG（数百实体），需要从大规模名词列表（数千~数万条）中扩展新实体并构建语义关系。

---

## 三信号融合公式

```
Score(noun, entity) = W1 * name_jaccard + W2 * tfidf_cosine + W3 * mention_boost
```

| 信号 | 权重 | 计算方法 | 值域 | 捕获什么 |
|------|------|---------|------|---------|
| name_jaccard | 0.30 | jieba 词性分词(只取名词/动词)后 token 集合 Jaccard 相似度 | [0, 1] 连续 | 名称概念重叠 |
| tfidf_cosine | 0.55 | TF-IDF 向量化(sublinear_tf, bigram, max_features=20000) + 余弦相似度 | [0, 1] 连续 | 描述语义相似 |
| mention_boost | 0.15 | 名词解释中是否直接提及已有实体名称 (0 或 1) | {0, 1} 二值 | 显式引用关系 |

> **权重设计原则**: tfidf_cosine 是唯一的连续语义信号，应占主导 (0.55)。mention_boost 是二值信号，
> 乘以权重后贡献要么 0 要么 0.15——不应超过中等 TF-IDF 相似度 (0.55*0.27=0.15) 的贡献，
> 避免偶然提及被过度放大。name_jaccard 覆盖名称层，权重 0.30。

### 信号互补性

- name_jaccard 捕获 "退款限额" ↔ "退款总控" 共享"退款"（名称层精确匹配）
- tfidf_cosine 捕获名称不同但描述语义相关的概念（**核心信号，决定多数关系**）
- mention_boost 捕获解释中的直接引用（辅助增强，但易被高频词干扰，权重已降至 0.15）

---

## 关键优化

### 优化1: 高频实体去噪 (来自 RAGAS)

统计所有名词解释中每个已有实体名被提及的频率，去除 Top-5% 高频实体（如"商户""支付""交易"）在 name_jaccard 和 mention_boost 信号中的参与。这些词匹配所有名词但不携带区分度。TF-IDF 信号不需要手动去噪（IDF 自动降权高频词）。

```python
# 统计每个已有实体名在名词解释中出现的频率
name_to_id = {e['name']: e['id'] for e in existing_entities}
mention_freq = Counter()
for desc in all_noun_descs:
    for entity_name, entity_id in name_to_id.items():
        if len(entity_name) >= 2 and entity_name in desc:
            mention_freq[entity_id] += 1
# 去除出现频率 Top-5% 的实体——这些词匹配所有名词但不携带区分度
noise_cutoff = max(1, int(len(existing_entities) * 0.05))
noisy_ids = set(eid for eid, _ in mention_freq.most_common(noise_cutoff))
# noisy_ids 同时用于 name_jaccard 和 mention_boost 两个信号的去噪
```

### 优化2: jieba 词性增强

实体名称分词时使用 `jieba.posseg` 词性标注，只保留名词(n/vn/nz)和动词(v)参与 Jaccard 计算，过滤虚词和修饰词。

> name_jaccard 也使用 noisy_ids 去噪：如果 v1 实体属于高频去噪集合，
> 则该实体不参与 name_jaccard 信号的计算（s1 直接置 0）。

### ~~优化3: 单信号 Top-K 保底~~ (v2-三信号版引入，后废弃)

> **废弃原因**: P1 评估实测 candidate_associates 层 Precision 仅 8%，P2 加权 Precision 0.27。
> 单信号救回的关系绝大多数是噪声，引入的负面影响远大于收益。
> 现改为：融合分低于阈值一律不建立关系，不再做单信号救回。

### 优化4: 度中心性剪枝 (来自 KGTrimmer SIGIR 2024)

如果一个已有实体被超过 MAX_DEGREE(300) 条名词关联，只保留权重最高的 300 条关系。剪枝时确保每个名词至少保留 1 条关系。

## 阈值配置（经四维质量评估 + 实测验证）

> 以下阈值经 P0~P3 四维评估 + 三档阈值实测验证。

| 参数 | 推荐值 | 验证依据 | 设太低的后果 |
|------|--------|---------|------------|
| SCORE_THRESHOLD | **0.15** | 实测: 0.15 保留 5,070 关系覆盖 2,409 名词(32.5%)；0.20 仅覆盖 1,132 名词(15.3%)，过于激进 | 0.10 → 92.8% 噪声 |
| TOP_K | **5** | 实测平均关系数 2.1(阈值0.15时)，Top-5 足够 | 过高导致关系爆炸 |
| MAX_DEGREE | **300** | 实测 0.15 阈值时 max 度 499，收紧到 300 | 高频实体成噪声集散地 |
| noise_cutoff_pct | **0.05** | 实测 Top-20 去噪实体（商户/支付/交易等）符合预期 | 过低则噪声未充分过滤 |

> **已废弃的参数**: `rescue_threshold` 和 `fallback_min_tfidf` 已随 candidate_associates 层一起废弃。
> 融合分低于 SCORE_THRESHOLD 一律不建立关系。

### 阈值实测对比

| THRESHOLD | 保留关系 | 覆盖名词 | 断连名词 | Strong+Normal占比 | 平均关系/名词 | Max v1 度 |
|-----------|---------|---------|---------|------------------|-------------|----------|
| 0.10 | 25,338 | 7,421 (100%) | 0 | 7.3% | 3.4 | 615 |
| **0.15** | **5,070** | **2,409 (32.5%)** | **5,012** | **36.2%** | **2.1** | **499** |
| 0.20 | 1,836 | 1,132 (15.3%) | 6,289 | 99.9% | 1.6 | 157 |
| 0.25 | 708 | 528 (7.1%) | 6,893 | 100% | 1.3 | 47 |

### 阈值选择的根本困境

三信号融合算法在阈值选择上存在 **精度-覆盖率 trade-off**:
- 阈值高(0.20+): Precision 优秀但 85% 名词失去连接
- 阈值低(0.10): 覆盖率 100% 但 93% 是噪声

**根因**: 当前三信号（名称Jaccard + TF-IDF + 提及）对于大量操作性名词（如"商户入驻审核流程"）
与领域模型实体（如"参与方""交易订单"）之间缺乏有效的语义桥梁。这些名词的描述文本使用的词汇
与领域模型实体的描述词汇重叠度低，导致 TF-IDF 信号不足。

**推荐策略**: 采用 THRESHOLD=0.15，接受 67.5% 名词断连（标注为独立名词节点），
而非为了 100% 连通率强制制造垃圾关系。

## 关系类型与权重映射

| 融合分数 | 关系类型 | 语义 | P1 实测 Precision |
|---------|---------|------|------------------|
| >= 0.40 | `strongly_associates` | 强关联 — 概念高度相关 | **96%** |
| 0.25~0.40 | `associates` | 关联 — 业务上相关 | **80%** |
| 0.15~0.25 | `weakly_associates` | 弱关联 — 有一定关系 | ~40-60% (实测 weakly 整体 24%，但 0.15~0.25 区间应高于全层平均) |
| < 0.15 | 不建立关系 | — | — |

> **已移除 `candidate_associates` 层**。P1 实测该层 Precision 仅 8%，废弃单信号救回机制。
> 断连名词（融合分全部 < 0.15）保留为独立名词节点，不强制制造垃圾关系。

每条关系携带 `weight` 字段（融合分数，0~1），下游消费者可按权重过滤。

## 已知局限与突破方向

### 精度-覆盖率困境

当前三信号算法的根本限制：THRESHOLD=0.15 覆盖 32.5% 名词，THRESHOLD=0.20 仅 15.3%。
67~85% 的名词无法与骨架实体建立有效关系。

**根因**: 三信号都是浅层文本特征，缺乏深层语义理解。"商户入驻审核流程" 与 "参与方" 之间的
关系需要理解 "入驻是成为参与方的过程"，但 TF-IDF 无法推理这种间接关联。

### 潜在突破方向（按可行性排序）

| 方向 | 方法 | 预估效果 | 依赖 |
|------|------|---------|------|
| **层级关系推理** | 名词→提取核心关键词→匹配已有实体的属性/枚举值→建立间接关系 | 覆盖率 +20%~30% | 纯 Python，无额外依赖 |
| **领域内增强** | 同 domain 的名词之间建立互关联（共享 domain = 弱关联证据） | 覆盖率 +40% 但精度需验证 | 纯 Python |
| **LLM embedding** | 用 sentence-transformers 替代 TF-IDF 做语义向量 | 精度 +15%~25%（语义理解更深） | sentence-transformers + 模型下载 |
| **LLM 批量判断** | 对高分不确定关系用 LLM 做 Yes/No 判断 | 精度 +10%，成本中等 | LLM API |
| **图传播** | 已连通名词的邻居信息传播到断连名词（label propagation） | 理论上可覆盖全部名词 | networkx |

### 已实现: 二次图推理 (Stage 4h)

**效果**: 覆盖率从 32.8% 提升到 **72.7%**，断连从 67.2% 降到 **27.3%**。

**算法**（零额外依赖，在三信号融合之后作为 Step 4h 执行）：

```
对每个断连名词:
  1. 多源关键词提取:
     a. jieba.cut 全切分（不限 POS，覆盖复合词拆分）
     b. 域前缀关键词（名词被选入图谱时匹配的 FILTER_KEYWORD）
     c. 名称 2 字符滑动窗口子串（过滤虚词）
  2. 桥接实体发现（三种方法并行）:
     a. 关键词匹配 v1 实体名（含高频噪声实体）
     b. 名词解释中提及 v1 实体名（>=3字符）
     c. 名词名称/关键词匹配 v1 实体的枚举值或 notes 列举项
  3. 渐进多跳（1→2→3→4→5 跳），逐级扩展 v1 邻居
  4. 用 TF-IDF 余弦对所有候选（桥接+邻居）评分
  5. 取 Top-3，建立 graph_inferred 类型关系（权重打 0.8 折扣）
```

**推理路径示例**:
- `商户入驻` → 关键词"商户" → 桥接 `E_PARTICIPANT_商户` → 1跳 `E_PARTICIPANT_参与方` → `graph_inferred`
- `结算卡变更` → 前缀"结算" → 桥接 `E_TRADE_交易结算单` → 多跳达到受益/账户实体 → `graph_inferred`
- `普通红包` → 枚举匹配 `E_SNS_KNOWLEDGE_个人交易类型` 的枚举值 → `graph_inferred`

**关键设计决策**:
- **jieba 全切分替代 POS 过滤**：POS 过滤导致 "付款明细""支付受限" 等短复合词提取为空集；全切分 + 2字符子串组合覆盖率更高
- **渐进 5 跳**：v1 图平均度 ~3，5跳理论覆盖 ~243 实体，但 TF-IDF 评分保证只保留语义相关的目标
- **枚举值/notes 索引**：预构建 v1 实体的枚举值和 notes 列举项索引，名词名称或关键词命中时直接桥接到父实体
- **不修改三信号 TF-IDF**（曾尝试图扩展 v1 文本，反而降低覆盖率 —— 扩展稀释了 TF-IDF 信号）
- **允许匹配高频噪声实体**（图推理阶段恢复使用噪声实体作为桥梁）
- **权重打折 0.8**：标记为间接推理，下游按需过滤
- **只作用于断连名词**：已连通的名词不受影响

**迭代演进**:

| 版本 | 方法 | 连通名词 | 断连 |
|------|------|---------|------|
| v1 (三信号 only) | Jaccard+TF-IDF+mention | 2,462 (33.2%) | 66.8% |
| v2 (1跳, jieba关键词) | +图推理(1跳) | 5,398 (72.7%) | 27.3% |
| v3 (2跳, 多源关键词) | +前缀/子串关键词, +2跳 | 6,581 (88.7%) | 11.3% |
| v4 (5跳, 全切分, 枚举匹配) | +jieba全切分, +5跳, +枚举索引 | 6,639 (89.5%) | 10.5% |
| **v5 (+词根泛化)** | +20个词根→v1概念的IS-A/PART-OF映射(Stage 4i) | **7,421 (100%)** | **0%** |

### 已实现: 词根泛化连通 (Stage 4i)

**效果**: 覆盖率从 89.5% 提升到 **100%**，0 断连。

**原理**: 所有名词都是按 43 个业务关键词前缀筛选进来的。剩余断连名词都能提取到一个词根（优惠券/红包/冻结/密码等），这些词根在领域建模中有明确的 IS-A 或 PART-OF 关系到 v1 概念：

| 词根 | 泛化目标(v1实体) | 领域建模关系 |
|------|----------------|------------|
| 红包 | 个人交易类型 | IS-A（红包是个人交易类型的一种） |
| 冻结 | 管控记录/管控包 | PART-OF（冻结是管控的一种动作） |
| 入驻 | 参与方/参与方关系 | 过程→结果（入驻是成为参与方的过程） |
| 付款 | 交易支付单 | 动作→单据（付款行为产生支付单） |
| 对账 | 交易结算单 | 验证→对象（对账验证结算单） |
| ... | ... | ... |

**关系类型**: `generalized_associates`，权重固定 0.10（标记为泛化推理）。

**关键特征**: 这是唯一需要**人工领域知识**的步骤（20 条 ROOT_GENERALIZATION 映射），其余步骤都是自动化的。

### 进阶指标（需额外标注或工具，按成本从低到高排列）

#### 1. LLM-as-Judge Precision@K（低成本，可自动化）

**依据**: GraphJudge (EMNLP 2025) — 用 LLM 作为"图谱法官"验证关系正确性，实验证明与人工标注相关性高。

> **重要**: 必须用真正的 LLM (如 GPT-4/Claude) 做判断，不能用规则匹配模拟。
> 本项目 v2 评估中因条件限制使用了规则模拟（标注为 Rule-based Judge），严谨性不足。

**实现步骤**:
1. 按权重分层抽样 100 条关系（强关联 30 + 普通 40 + 弱 30）
2. 对每条关系构造 prompt，让 LLM 判断是否合理：
   ```
   名词: {noun_name}
   名词解释: {noun_description}
   关联实体: {v1_entity_name}
   实体描述: {v1_entity_description}
   关系权重: {weight}
   
   请判断这两个概念是否存在业务关联（是/否/不确定），并给出理由。
   ```
3. 统计 Precision = 判断为"是"的比例
4. 合格线: Precision@100 >= 0.70（强关联层应 >= 0.90）

**成本**: ~100 次 AI 调用，几分钟完成。可用 Cursor 对话或 MCP 工具执行。

#### 2. 分层抽样人工 Precision（中成本）

**依据**: SIGMOD 2025 Credible Intervals (CrIs) — 贝叶斯统计抽样估计 KG 准确率，比全量标注降低 60~80% 成本。

**实现步骤**:
1. 将关系按 (relation_type, domain) 分层
2. 每层随机抽样 n 条（总计 ~200 条）
3. 领域专家判断每条关系: 正确(1) / 错误(0) / 不确定(0.5)
4. 计算分层加权 Precision 和 95% 置信区间
5. 合格线: 加权 Precision >= 0.70，95% CI 下界 >= 0.60

**成本**: 领域专家 1~2 小时标注 200 条。

#### 3. 稀疏度指标 (MINE 风格，零成本)

**依据**: MINE 基准 (arxiv 2502.09956) — 衡量图谱的信息密度而非精度。

**实现步骤** (可直接用 Python 计算):
```python
unique_relation_types = len(set(r['relation_type'] for r in relations))
total_edges = len(relations)
sparsity = unique_relation_types / total_edges  # 越低越好
avg_degree = 2 * total_edges / total_entities
density = total_edges / (total_entities * (total_entities - 1))
```

| 指标 | 公式 | 合格线 | 说明 |
|------|------|--------|------|
| 关系类型稀疏度 | unique_types / total_edges | < 0.01 | OpenIE 通常接近 1.0（每条边一个类型），好的 KG < 0.01 |
| 平均度 | 2E / V | 2~8 | DBpedia ~7；名词扩展场景 2~4 |
| 图密度 | E / V(V-1) | 极小但非零 | 大图天然稀疏，关注变化趋势而非绝对值 |

**成本**: 零（纯计算）。

#### 4. 负样本对比 AUC-PR（中高成本）

**依据**: Link Prediction 评估标准 (arxiv 2502.12777) — 推荐 AUC-PR 优于 AUC-ROC（因正负样本极度不平衡）。

**实现步骤**:
1. 正样本: 现有关系中人工确认正确的 ~200 条
2. 负样本构造: 对每条正样本，随机替换 head 或 tail 生成 corrupted triple
3. 用三信号融合分数作为预测值
4. 计算 AUC-PR 曲线
5. 合格线: AUC-PR >= 0.60

**成本**: 需要 ~200 条人工标注正样本 + Python 计算。

#### 实施优先级建议

| 优先级 | 指标 | 理由 |
|--------|------|------|
| P0 (立即可做) | 稀疏度指标 | 零成本，纯计算 |
| P1 (推荐做) | LLM-as-Judge Precision@K | 低成本，需真正调用 LLM，不能用规则模拟 |
| P2 (有余力时做) | 分层抽样人工 Precision | 需领域专家参与 |
| P3 (学术研究时做) | AUC-PR | 需标注正样本 + 构造负样本 |
