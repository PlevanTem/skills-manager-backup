MEP 热升级双镜像方案

解决新旧 IMEM 格式不兼容，实现无损在线升级

背景与目标

为什么需要热升级方案

MEP 微码更新频率较高（约每 2 周一次），当前升级流程需要停流，影响生产环境稳定性。新版微码引入了 CT 状态域段，导致 IMEM 格式与旧版不兼容，无法直接覆盖升级。

方案概述

双镜像切换架构

热升级流程
┌──────────────────────────────────────────────────────────────┐
│                    热升级流程 (7 步)                          │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  ① Mask 背景线程      ──→  停止新报文调度到目标 Quark         │
│          │                                                    │
│  ② Quark 状态 Check   ──→  等待所有在飞报文处理完成           │
│          │                                                    │
│  ③ CME Disable         ──→  停止 CME 线程                    │
│          │                                                    │
│  ④ Load 新 IMEM        ──→  加载到 Bank B（当前运行 Bank A）   │
│     Load 新 DTCM       ──→  更新 rodata                      │
│          │                                                    │
│  ⑤ 配置 CSR            ──→  更新 start_pc、hash_seed 等      │
│          │                                                    │
│  ⑥ CME Enable          ──→  重新使能线程，指向 Bank B         │
│          │                                                    │
│  ⑦ Unmask 背景线程     ──→  恢复报文调度                     │
│                                                              │
│  ┌─────────┐  ┌─────────┐                                    │
│  │ Bank A  │  │ Bank B  │   ← 双 Bank 同时存在               │
│  │ (旧版)  │  │ (新版)  │   ← 切换后 Bank A 可用于下次升级    │
│  └─────────┘  └─────────┘                                    │
└──────────────────────────────────────────────────────────────┘

核心思路：利用 IMEM 的 Bank 机制，将新版镜像加载到备用 Bank，通过 CSR 切换指令入口地址实现瞬时切换。整个过程对已在处理的报文无影响。

方案对比

双镜像 vs 格式兼容层

方案 A: 双镜像切换 ✅ 推荐
  • 原理：新旧 IMEM 各占一个 Bank，通过 CSR 切换
  • 空间消耗：16KB/Quark（总 32KB 的 50%）
  • 切换延迟：< 1ms（仅 CSR 写入）
  • 回滚能力：秒级回滚（切回旧 Bank）
  • 代码改动：仅控制面升级流程，微码零改动
  • 风险：IMEM 空间减半，需确保微码 < 4K 条指令
方案 B: 格式兼容层 ✗ 否决
  • 原理：新版微码内嵌旧格式解析逻辑
  • 空间消耗：仅占额外 ~200 条指令
  • 切换延迟：~30s（需停流重加载）
  • 回滚能力：需要重新加载旧版镜像
  • 代码改动：微码增加兼容逻辑，增加复杂度
  • 风险：每次新增域段都要维护兼容逻辑

⚠️ 最大风险：IMEM 空间限制
双镜像方案将可用 IMEM 从 8K 条指令减至 4K 条。当前微码约 3.2K 条指令，剩余空间 ~20%。缓解措施：设置编译时指令数检查，超过 3.8K 条自动告警。
