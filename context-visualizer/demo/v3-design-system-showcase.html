改造历程

从发现问题到完成改造的关键节点

2026-03-26
v2 版本上线
完成基于 Python 渲染器的最小闭环，支持 4 种场景和 2 种主题。
2026-03-27 上午
发现瓶颈
用户反馈：AI 分析 Markdown 后无法补充流程图、代码块被渲染为纯文本、表格丢失。
根因：Python 渲染器是"忠实翻译器"，不理解内容，不能增强内容。AI 在生成 Markdown 的那一刻就丧失了对 HTML 的控制权。
2026-03-27 下午
确定改造方案
方向：干掉 Python 中间层，转型为 CSS 设计系统 + 提示词规范。AI 直接输出 HTML。
2026-03-27 晚上
v3 改造完成
完成全部改造：SKILL.md 重写、CSS 组件库扩展（12+ 组件）、组件参考手册编写、demo 验证。

v2 完全无法渲染的代码块，现在原生支持

C mep_sdk/session.c 
/* 添加 session 表项到 MEP */
int jnet_session_tbl_add(struct session_entry *entry) {
    if (!entry)
        return JNET_ERR_PARAM;

    // 校验 key 模板和 action 格式
    int ret = validate_session_key(entry->key, entry->key_mode);
    if (ret != JNET_OK)
        return ret;

    // 通过 TSE 写入外部流表
    return tse_em_add(entry->table_id, entry->key, entry->action);
}
