## 🔤 字体安装说明（重要）

> ⚠️ **使用前必读**：本技能生成的 PPT 需要使用**腾讯体 W7** 和 **腾讯体 W3** 字体。技能包已内置这两个字体文件，但需要手动安装到系统中。

### 字体文件位置

技能包内置字体路径：
```
~/.workbuddy/skills/Tenchage-ppt/fonts/
├── 腾讯体 W3.ttf   ← 常规体（正文使用）
└── 腾讯体 W7.ttf   ← 粗体（标题使用）
```

### Windows 安装步骤

1. 打开文件资源管理器，导航到：
   ```
   C:\Users\你的用户名\.workbuddy\skills\Tenchage-ppt\fonts\
   ```

2. 右键点击 `腾讯体 W3.ttf` → 选择「**安装**」或「**为所有用户安装**」

3. 右键点击 `腾讯体 W7.ttf` → 选择「**安装**」或「**为所有用户安装**」

4. 安装完成后，**重启 PowerPoint** 使字体生效

### macOS 安装步骤

1. 在 Finder 中打开：
   ```
   ~/.workbuddy/skills/Tenchage-ppt/fonts/
   ```

2. 双击 `腾讯体 W3.ttf` → 点击「**安装字体**」

3. 双击 `腾讯体 W7.ttf` → 点击「**安装字体**」

4. 安装完成后，重启 PowerPoint 使字体生效

### 验证安装是否成功

打开 PowerPoint → 新建文本框 → 字体下拉列表 → 查找「**腾讯体 W7**」和「**腾讯体 W3**」

### 未安装字体的后果

- PPT 生成后打开时，PowerPoint 会自动替换为系统默认字体
- 会导致**排版错乱**、**文字溢出**、**视觉效果与预期不符**

### SOP 3：快速修复常见布局问题
**问题 1：主标题文字溢出**
- 原因：标题超过 40 个中文字符
- 修复：自动截断到 40 字 + "..."，或在 JSON 中手动精简标题

**问题 2：卡片内容文字溢出**
- 原因：desc 字段文字过多
- 修复：缩小字号到 12pt（最小不低于12pt，v3.7版面规范），仍溢出则截断末尾加 "..."

**问题 3：页码与内容碰撞**
- 原因：内容区最后一行距离底部太近
- 修复：调整内容区最大高度 `maxH`，或缩减内容文字

**问题 4：中文旋转后乱码**
- 原因：pptxgenjs 对中文旋转支持不佳
- 修复：改用英文表达，或取消旋转（改为水平排列）

### SOP 4：SVG 中转生成可编辑 PPT（默认最终输出格式）

**触发场景**：任何需要通过 SVG 中转路径生成 PPT 的场景（流程图、链路图、架构图、复杂信息图等），最终产物**必须是文字可编辑的原生 PPT**，而非图片贴图版。

> ⚠️ **铁律**：凡走 SVG 中转路径的 PPT，最终输出**必须是原生可编辑 DrawingML 形状**（文字可选中、可修改），禁止把 SVG 整页渲染为 PNG 图片嵌入。这是与 v3.3 混合路线的区别——v3.3 允许「复杂图表区域」以图片嵌入，但 SVG 中转链路的目的就是获得全页可编辑效果。

> ### 🎯 SVG 中转版面铁律 v3.9.4（哈哥 2026-07-04 拍板，针对 C 路径）
>
> **1. 布局铺满铁律（v3.9.4 新增）**
> - viewBox 1280×720 是固定画布，**内容主体区必须铺满**（左右边距 ≤ 30px、上下边距 ≤ 30px）
> - **禁止内容聚在左上 < 800×500 区域**导致右下空白——必须让元素的 `x+width` 接近 1280、`y+height` 接近 720
> - 内容不足时，**必须用装饰元素（彩色块/虚线框/小图标/底色矩形/角部装饰）补满**右下空间，不允许出现明显空白
> - 卡片网格必须**横向拉伸到 1220px 宽**（左右各 30px 边距），不允许卡片只占页面 1/3 宽
> - 多个段落/卡片必须**纵向铺到 690px 高**（顶部 30px 标题区 + 底部 30px 页码区之间），不允许内容集中在上半页
>
> **2. 字号下限铁律（v3.9.4 升级，仅 C 路径）**
> - 哈哥要求 SVG 中转路径字号**必须大于 PPT 中的 12 号字**（即 SVG font-size > 16px）
> - **C 路径正文最小字号 14pt**（SVG font-size 18.7px），下限比 A/B 路径（12pt/16px）更严
> - 转换后实际渲染：12pt 不允许作为正文最小档；14pt (18.7px) 起步；18pt (24px) 为主；24pt (32px) 为标题；封面/结尾大标题 36pt (48px)
> - A/B 路径字号规则不变（v3.9.2 的 12pt 下限仍生效）

**核心技术要点**：

| 要点 | 说明 |
|------|------|
| **SVG viewBox 必须 1280×720** | 本技能的 `svg_to_pptx.py` 按 `EMU_PER_PIXEL = 914400/96` 直接映射 SVG 坐标到 PPT EMU 单位。标准 16:9 PPT = 12192000×6858000 EMU = 1280×720 像素。viewBox 非 1280×720 会导致元素溢出页面边界 |
| **字体必须腾讯体** | **禁止用 `<style>` 和 `class`**（转换器不读它们）。font-family 必须直接写在每个 `<text>` 元素属性上：`font-family="腾讯体 W7"`（标题）或 `font-family="腾讯体 W3"`（正文）。转换器 EA_FONTS 已注册这些字体名 |
| **字号换算铁律** | 1 SVG px = 0.75 PPTX pt（`FONT_PX_TO_HUNDREDTHS_PT=75`）。目标12pt→SVG写16、14pt→18.7、18pt→24、24pt→32。**C 路径正文字号下限**（v3.9.4 哈哥升级）：PPTX中**不低于14pt** → SVG中 font-size **不低于18.7**（哈哥原话："字号必须要大于PPT中的12号字"） |
| **所有坐标 ≤ 1280×720** | 元素 x+width ≤ 1280，y+height ≤ 720，否则溢出右/下边界 |
| **转换工具** | `python svg_to_pptx.py <project_dir> -s output --only native -f ppt169 -a none`（本技能自带） |

**完整步骤**：

1. **设计 SVG**
   - viewBox 固定为 `0 0 1280 720`
   - **禁止使用 `<style>`、`class`、`@font-face`**（转换器不解析这些）
   - 字体直接写在每个 `<text>` 元素属性上：
     ```xml
     <!-- 标题文字（一级 24pt = 32px） -->
     <text x="30" y="40" font-family="腾讯体 W7" font-size="32" font-weight="700" fill="#1D2129">标题</text>
     <!-- 正文文字（二级 18pt = 24px） -->
     <text x="30" y="70" font-family="腾讯体 W3" font-size="24" font-weight="400" fill="#86909C">正文</text>
     <!-- 注释文字（三级 12pt = 16px） -->
     <text x="30" y="95" font-family="腾讯体 W3" font-size="16" font-weight="400" fill="#86909C">注释</text>
     ```
   - 字号单位为SVG px，目标pt值需除以0.75得到SVG px值
   - 所有文本用 `<text>` 元素（非 `<path>` 描边），确保转换后可编辑
   - 形状用 `<rect>`, `<circle>`, `<polygon>`, `<line>` 等基础元素

2. **创建项目目录结构**
   ```
   <project_name>/
   └── svg_output/
       ├── 01_page_name.svg
       ├── 02_page_name.svg
       └── ...
   ```

   > **图片/箭头嵌入铁律（v3.8.2 哈哥实战沉淀）**：
   > - `svg_to_pptx` **支持** `<image>` 元素，href 用 `data:image/png;base64,...` 内联最稳（避免相对路径丢失）。
   > - **不支持 `<clipPath>`**（报 `unsupported visual SVG element(s): clipPath`）。需要圆角图片时，**必须在 Pillow 端先把图片裁成圆角透明 PNG**（`ImageDraw.rounded_rectangle` 做 alpha 遮罩），SVG 里直接 `<image preserveAspectRatio="none">`，不要用 clipPath。
   > - **不支持自定义 `<marker>` 箭头**（只认 triangle/diamond/oval，常分类失败被跳过）。画箭头用 `<line>` + `<polygon>` 实心三角自己拼。
   > - 图片防糊：Pillow 按显示尺寸×3 倍渲染再嵌入。

3. **执行转换**
   ```bash
   python ~/.workbuddy/skills/Tenchage-ppt/scripts/svg_to_pptx.py <project_dir> \
     -s output --only native -f ppt169 -a none -o <输出文件名>.pptx
   ```
   - `-s output`：从 `svg_output/` 读取源文件
   - `--only native`：只生成原生 DrawingML 版本（可编辑），不生成 SVG 嵌入版
   - `-f ppt169`：16:9 画幅
   - `-a none`：不加入口动画（保持简洁）

4. **验证结果**
   - 打开 PPTX 确认文字可选中、可编辑
   - 确认无元素溢出页面边界
   - 确认字体正确渲染为腾讯体

**字号参考表（v3.9.4 哈哥拍板，SVG 中转路径专用，SVG font-size px → PPTX 实际 pt，换算：pt = px × 0.75）**：

> ⚠️ **哈哥拍板铁律（v3.9.4 SVG 中转路径）**：字号3级制——标题24pt封顶、二级18pt、三级**14pt下限**。全页字号范围14-24pt，禁止中间档位（15/16/17pt等），禁止使用 12pt 作为正文。封面/结尾大标题允许放大至36pt(48px)。核心原则——**排版不是美化，是信息分级——让读者不用思考就知道先看哪**。

**重点突出手法（v3.7 新增）**：

> 5种手法按力度从强到弱，组合使用效果最佳。

| 手法 | 力度 | 实现方式 | 适用场景 |
|------|------|---------|---------|
| **1. 字号放大** | ★★★★★ | 关键数字用24pt，旁边描述用12pt | 核心数据/关键结论 |

### 5.6 Refined C-path 默认视觉标准（2026-07-15 起）

C 路径（SVG 中转）默认采用**精修视觉（v2 风格固化）**：卡片带图标 chip、配色按能力轮换、封面/结尾分层渐变+装饰圆、页面更饱满。目标——不单调、有设计感，但仍 100% 原生可编辑。

**强制项（C 路径默认，除非用户明确要求极简）**：
1. **内容卡片必须带图标 chip**：圆角浅蓝底 `#EAF0FF` + 品牌色线性图标。图标用 `scripts/svg_icons.py` 的 `render_icon(name, cx, cy, color, k)`，`ICON_NAMES` 现内置 **66 枚**且持续扩充（原24 + 新增 rocket/star/heart/trophy/flag/bulb/gift/coin/pie/trend/globe/mail/phone/bell/clock/cloud/lock/pin/compass/eye/filter/sync/pencil/plus/arrow/crown/briefcase/scale/database/server/code/cpu/terminal/sliders/play/pause/stop/minus/close/sun/wifi/map）。需要新图标：往 `ICON_NAMES` 加名字 + 在 `render_icon` 加一个 `elif` 分支（只用 line/polyline/polygon/circle/rect 基础形状，保证 svg_to_pptx 可转换）。完整清单见 `icon_test/icons_check.pptx` 图示。
2. **卡片强调色按能力轮换**：`refined_deck.HUBS = [MAIN(#1A50D6), BRIGHT(#2E6CFF), GREEN(#00A45D), DEEP(#0E2F7E), MID(#4E82C5), LIGHT(#7CB3E0)]`，制造配色多样性。仅用品牌色板，不引入禁色。

3. 同页同类图标风格统一：不要 outline + filled 混用
4. 一个页面图标不超过 5 个，避免"图标墙"视觉噪音
5. 替代 emoji 规则：新版式优先使用 `add_icon()`，旧版式保留 emoji 兼容
6. 图标搜索失败时自动 fallback 到无图标（不报错，不阻断生成）

**图标颜色注入原理**：
`add_icon()` 读取 SVG 后自动替换 `stroke` 和 `fill` 属性为指定颜色，通过 `svg_renderer` 渲染为 PNG 嵌入。支持透明背景，与 PPT 底色融合。

### 5.6.1 半透明 + 渐变填充规范（v3.9.0 新增，学自 ppt-master）

在纯色 `set_fill()` 之外，新增两个填充函数，用于做出更有质感的标题条、金句条、标签胶囊、流量池框等。**直接操作 DrawingML XML，PowerPoint 渲染正常。**

**调用方式**（`tenchage_v32_layouts.py`）：
```python
from tenchage_v32_layouts import set_fill_alpha, set_fill_gradient

# 半透明纯色（alpha 0.0 全透明 ~ 1.0 不透明）
set_fill_alpha(shape, C_PRIMARY, alpha=0.6)

# 双色线性渐变（angle: 0=左→右, 90=上→下, 45=左上→右下）
set_fill_gradient(shape, '#2E7D55', '#1F5C3D', angle=90)

# 三色渐变 + 整体半透明
set_fill_gradient(shape, '#1A50D6', '#00A45D', '#0E2F7E', angle=45, alpha=0.8)
```

**设计铁律**：
1. 渐变只用同色系或腾讯蓝/绿主辅色，**禁止彩虹渐变**（违背腾讯商务调性）
2. 标题条/金句条优先用「深色→主色」竖向渐变（angle=90），增强厚重感
3. 半透明叠加在图片/背景上时 alpha 建议 0.5-0.7，纯底色上用 0.85-1.0
4. 渐变是「锦上添花」，正文卡片仍以纯色/白底为主，一页渐变元素不超过 3 处
5. 颜色参数支持 `RGBColor` / `'RRGGBB'` / `'#RRGGBB'` / `(r,g,b)` 四种写法

### 5.6.1.1 弥散投影规范（v3.9.6 新增，补齐 B 路径阴影缺口）

A 路径（pptxgenjs）的卡片一直有 `shadow: {type:'outer', blur, offset, angle, color, opacity}` 参数，但 B 路径（python-pptx）此前没有对应函数——`cards_outlined` 等描边卡片版式因此只能"无阴影"。v3.9.6 补上 `set_shadow()`，两路径阴影参数语义对齐。

**调用方式**（`tenchage_v32_layouts.py`）：
```python
from tenchage_v32_layouts import set_shadow, C_SHADOW

# 卡片标准弥散投影（对齐 A 路径 cards 布局默认参数）
set_shadow(shape, blur=10, offset=3, angle=90, color=C_SHADOW, opacity=0.5)
```

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `blur` | 模糊半径（pt） | 10 |
| `offset` | 投影偏移距离（pt） | 3 |
| `angle` | 投影方向角度，0=右/90=下/180=左/270=上 | 90（向下） |
| `color` | 阴影颜色 | `'000000'`（建议卡片场景传 `C_SHADOW` = `#E0E6F1` 浅蓝灰） |
| `opacity` | 不透明度 0.0-1.0 | 0.5 |

**C 路径（SVG 中转）等效写法**（`svg_to_pptx/drawingml_styles.py` 的 `build_shadow_xml()` 已支持解析 SVG 标准阴影滤镜，无需额外开发）：
```xml
<defs>
  <filter id="cardShadow" x="-20%" y="-20%" width="140%" height="140%">
    <feDropShadow dx="0" dy="3" stdDeviation="5" flood-color="#E0E6F1" flood-opacity="0.5"/>
  </filter>
</defs>
<rect x="60" y="120" width="280" height="200" rx="8" fill="#FFFFFF" filter="url(#cardShadow)"/>
```
（`stdDeviation` 约等于 `blurRad(pt) / 2`，即 blur=10pt → `stdDeviation≈5`；`dy` 对应 offset 方向的竖直分量）

**设计铁律**：
1. 阴影是「让卡片浮起来」的轻量质感手法，不是装饰重点——同一页所有卡片阴影参数必须一致，禁止逐张调不同 blur/offset
2. 默认方向 `angle=90`（向下投影），符合常规光源逻辑，禁止随意改斜向（45°）除非有特殊构图需求
3. 阴影颜色优先用色板 `E0E6F1`（浅蓝灰），禁止用纯黑阴影（显脏、不符合腾讯商务调性）

### 5.6.2 配图能力规范（v3.9.0 新增，学自 ppt-master）

为场景化卡片、封面、产品展示页生成写实配图，**用 WorkBuddy 内置 `ImageGen`，零配置无需 API key**。

**标准流程**（主 agent 哈小助侧）：
1. **声明需求**：版式脚本里用 `image_helper.ImageManifest` 登记每张配图的 `name` + `prompt` + `aspect_ratio`，导出 `image_manifest.json`
2. **逐张生图**：主 agent 读取 manifest，对每条 prompt 调 `ImageGen`（`output_dir` 指向项目 images 目录），生成后按 manifest 的 `name` 重命名
3. **裁剪嵌入**：版式脚本用 `crop_cover(src, out, w, h)` 把图居中裁成卡片宽高比（等同 object-fit:cover，不变形不留白），再 `add_picture` 嵌入
4. **兜底**：未生图时 `make_placeholder()` 生成腾讯风格占位图，不至于空白

**提示词预设**（`PROMPT_PRESETS`，腾讯零售场景）：
`retail_store`（到店选购）/ `delivery`（O2O 送货）/ `ecommerce`（电商包裹）/ `mini_program`（小程序）/ `office_meeting`（会议）/ `data_center`（数据看板）。用 `preset_prompt('retail_store', extra='额外描述')` 取用。

**配图铁律**：
1. prompt 必须含 `photorealistic, commercial photography, no text, no watermark`，避免图里出现乱码文字
2. 中文场景用英文 prompt 更稳定（避免出现错误的中文字符）
3. 同一页多张配图风格统一（都写实 / 都插画，不混搭）
4. 配图是场景烘托，不承载核心信息——关键数据/结论仍用可编辑文字
5. 默认 `quality: high`，封面大图用 `1024x1536`，卡片配图用 `1024x1024` 再裁剪

### 5.7.1 蓝色底色默认渐变规则（v3.9.5 哈哥拍板，2026-07-08）

> ⚠️ **铁律**：凡是**蓝色底色/蓝色实心 banner**（标题条、章节分隔条、金句条、封面主色块等大面积蓝色填充），**默认使用水平双色渐变**，禁止纯色 `#1A50D6` 平铺。参考案例：《AI 赛训评委 TOP 精选》P9 顶部 banner。

**默认蓝色渐变参数**：

| 参数 | 值 | 说明 |
|------|-----|------|
| 起点色（左，深） | `#0E2F7E`（`C_PRIMARY_DEEP`） | 已有色板深蓝，无需新增 |
| 终点色（右，亮） | `#2E6CFF`（`C_BRIGHT_BLUE`） | 已有色板亮蓝，无需新增 |
| 方向 | 水平，左→右（`angle=0`） | 不是竖向，不是斜向 |
| 适用范围 | 大面积蓝色底色块（banner/标题条/封面色块） | 卡片竖条/装饰线等**小色块仍用纯色** `#1A50D6`，不套渐变 |

**B 路径（python-pptx）调用**：
```python

set_fill_gradient(shape, C_PRIMARY_DEEP, C_BRIGHT_BLUE, angle=0)
```

**C 路径（SVG 中转）写法**：
```xml
<defs>

    <stop offset="0%" stop-color="#0E2F7E"/>
    <stop offset="100%" stop-color="#2E6CFF"/>
```

（`drawingml_styles.py` 已支持 `linearGradient` → `<a:gradFill>` 原生转换，无需额外开发）

**A 路径（Node.js/pptxgenjs）例外**：pptxgenjs 的 `addShape` 渐变已知不渲染（见 5.8 禁止事项），A 路径蓝色 banner 仍用纯色 `#1A50D6` 平铺，**不受本规则约束**。

### 5.8 PPT版面规范（v3.7 哈哥拍板铁律）

> 核心原则：**排版不是美化，是信息分级——让读者不用思考就知道先看哪、再看哪、可以跳过哪。**

#### A. 字号阶梯（3级制）

| 层级 | 用途 | 字号 | 字重 | 字体 | 示例 |
|------|------|------|------|------|------|
| **一级** | Action Title / 核心结论 | **24pt** | Bold (700) | 腾讯体 W7 | "竞品A占据45%份额但增速下滑" |
| **二级** | 关键论点 / 小标题 | **18pt** | Medium (500) | 腾讯体 W3 | "市场份额"、"增速趋势" |
| **三级** | 常规正文 / 要点说明 | **12pt** | Regular (400) | 腾讯体 W3 | "为全家选高端奶"（正文下限） |

**硬边界（v3.9.2 哈哥拍板）**：
- 标题字号 = **24pt**，全页最大，不可超过（封面/结尾页大标题除外，允许放大至36pt）
- **正文最小字号 = 12pt**（v3.9.2 从 14 回调至 12），`add_text` 强制兜底自动抬升
- 仅页码 / logo / 右上角品牌标识 / 装饰角标可低于 12（传 `allow_small=True`，9-11pt）
- 低于 12pt 的正文投屏看不清——这是哈哥定的铁律

**中间档位**：
- **24pt** → 一级标题 / 核心结论
- **18pt** → 关键要点 / 小标题 / 卡片标题
- **14pt** → 常规正文说明
- **12pt** → 密集页正文 / 脚注（下限）

**铁律：禁止"半大不小"的中间字号**。不是14pt就是18pt，没有15pt、16pt这种档位——那叫噪音，不叫层级。级间比例 ≥ 1.3倍才有区分度。

**可读性底线**：

| 使用场景 | 正文最小字号 |
|---------|------------|
| 投影演示（会议室） | 18pt |
| 屏幕发送（邮件/微信） | 14pt |
| 手机阅读 | 16pt |

#### B. 行间距 & 段间距

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| **行间距** | 1.3 ~ 1.5 倍 | 1.0太紧挤成一团，1.8太松读不连贯 |
| **段间距** | 行间距 × 1.5 | 视觉上区分"同一段"和"换了一段" |
| **字间距（标题）** | +2% ~ +5% | 标题字少，松开更透气 |
| **字间距（正文）** | 0% | 正文字多，加宽反而散 |

**关键区分**：
- **行间距**控制"这行和下一行之间的关系"
- **段间距**控制"这一组信息和下一组信息之间的关系"
- **铁律：组间距 > 组内距**（至少2倍），这是亲密性原则的量化表达——同一组行紧密，不同组之间留明确空隙

#### C. 5种重点突出手法（按力度从强到弱）

**1. 字号放大（最强）**
关键数字放到正文2~3倍大小。`+37%` 用24pt，旁边"同比增长"用12pt。一眼锁定，无法忽略。

**2. 颜色高亮**
全页90%灰度文字，只给1~2处关键信息上品牌色。规则：**1主色（腾讯蓝#1A50D6）+ 1辅色，每页最多2处色块**。全高亮=没有重点。

**3. 字重对比**
腾讯体 W7 (Bold) vs W3 (Regular)，同字号下纯靠粗细区分。弱项用淡灰+W3，强项用深色+W7。

**4. 色块/底线标注**
- **色块底色**（强标注）：关键词后面加半透明色块，像荧光笔划线
- **底线**（轻标注）：数字下方2px色线，低调但有效

**5. 留白聚焦**
你希望观众看的地方，周围清空一切干扰。留白=聚光灯。一个24pt的数字周围什么都没有，比塞满信息的一页更有冲击力。

#### D. 组合拳

| 组合方式 | 力度 | 适用场景 |
|---------|------|---------|
| **字号放大 + 品牌色** | ★★★★★ | 核心数据 / 关键结论 |
| **字重对比(W7 vs W3) + 色块标注** | ★★★★ | 对比项 / 排名变化 |
| **底线 + 留白** | ★★★ | 次要强调 / 补充说明 |

**Before → After 示例**：
- Before：全部12pt灰色平铺，信息等权，读者自己找重点，3秒抓不到
- After：`+37%` 24pt品牌色放大 → "营收1.2亿" 12pt灰 → "毛利42%" 色块标注 → 1秒get

| `intro` | 可选 | 主标题下方的正文描述段。有 intro 时卡片区从 Y=1.70" 开始；无 intro 时从 Y=1.70" 开始（与 subTitle 共用空间） |
| `cards` | ✅ | 卡片数组，每张含 title / tag(可选) / desc |
| `cards[].tag` | 可选 | 标题旁的小标签文字，如"认知对齐"。渲染为**纯色蓝底**+白色文字的圆角小色块 |
| `cards[].desc` | ✅ | 字符串（换行分隔）或字符串数组。每行自动加 "·" 前缀 bullet |
| `footerBar` | 可选 | 页面底部的蓝色横条文字（适合放核心价值/总结语） |

> **⚠ pptxgenjs 限制**：`addShape` 不支持渐变填充（`stops` / `color1+color2` 均无效），标签色块统一使用**纯色填充**。
> 标签配色方案按序号轮替：前 3 张腾讯蓝 `#1A50D6`、4-5 张中蓝 `#4E82C5`、6 张浅蓝 `#7CB3E0`。

**布局自适应**：
- 3 张：单行 3 列
- 4 张：2×2
- 5-6 张：3 列 × 2 行（标准）
- 7-8 张：4 列 × 2 行

**核心尺寸参数**（以 6 张 3×2 为例）：
```
内容区宽 CW = 9.0", 左边距 M = 0.5"
列间距 colSpace = 0.25", 行间距 rowSpace = 0.25"
总内容高 maxH = 有footerBar时3.1" / 无footerBar时3.5"
列数 cols = 3, 行数 rows = 2
卡片宽 colW = (9.0 - 2*0.25) / 3 ≈ 2.83"
每行高 rowH = (maxH - rowSpace) / 2
编号标题行高 headerRowH = 0.35"
内容框高 contentH = rowH - headerRowH - 0.08"
```

**逐层渲染规则**：

#### A. intro 正文段（可选，卡片上方）
```
位置: x = M(0.5"), y = 1.15"
大小: w = CW(9.0"), h = 0.45"
字号: 12pt, 常规, 颜色 #4E5969（v3.7起从10.5pt提升）
行距: 1.3 倍
有 intro 时: 卡片区 startY = 1.70"
无 intro 时: 卡片区 startY = 1.70"
```

#### B. 编号 + 标题（卡片框外上方，合并为一个文本框）
```
文本框: x = cardX, y = cardY, w = colW * 0.6, h = headerRowH(0.35")
内容: "01  共识摸底"（编号两位 + 双空格 + 标题）
字号: 13pt, 粗体, 颜色 #1D2129 (深黑)
对齐: 左对齐, 垂直底部对齐
```

#### C. 标签色块（卡片行右上角，可选）
```
形状: roundRect (圆角矩形)
位置: x = cardX + colW - tagW（右对齐）
      y = cardY + (headerRowH - tagH) / 2 + 0.04"
大小: w = min(1.2", colW * 0.4), h = 0.22"
圆角: rectRadius = 0.04"
填充: 纯色（按序号轮替：1A50D6 / 4E82C5 / 7CB3E0）
边框: 无 (line: {type:'none'})
文字: 12pt, 粗体, 白色 #FFFFFF, 水平居中+垂直居中（v3.7起从8.5pt提升）
```

#### D. 内容描边框（圆角矩形）
```
形状: roundRect (圆角矩形)
位置: x = cardX, y = cardY + headerRowH + 0.05"
大小: w = colW, h = contentH
圆角: rectRadius = 0.08"
填充: 纯白 #FFFFFF
边框: color = E5EBF5(浅蓝灰), width = 1.0pt
阴影: 弥散投影 {blur:10, offset:3, angle:90, color:E0E6F1, opacity:0.5}（v3.9.6 起默认带阴影，与 cards 布局参数对齐）
```

#### E. 内容 Bullet 文字（描边框内）
```
文本框: x = cardX + 0.15", y = contentY + 0.1"
        w = colW - 0.30", h = contentH - 0.20"
内容: 每行 "· " + 文字（自动清除原有前缀后重加）
字号: 12pt, 常规, 颜色 #4E5969 (中灰)（v3.7起从10pt提升至12pt）
行距: 1.35 倍
对齐: 左对齐, 垂直顶部对齐
```

#### F. footerBar 底部横条（可选）
```
形状: roundRect (圆角矩形)
位置: x = M(0.5"), y = 页面底部上方 ≈ 4.875"
大小: w = CW(9.0"), h = 0.35"
圆角: rectRadius = 0.05"
填充: 腾讯蓝 #1A50D6
文字: 12pt, 粗体, 白色, 水平居中+垂直居中（v3.7起从9.5pt提升至12pt）
```

**完整渲染顺序（build_ppt.js 中）**：
1. 如有 `intro`，先渲染正文段 (A)，调整 startY
2. 计算网格位置（cols × rows）
3. 遍历 cards 数组，对每张卡片依次画：编号标题 (B) → 标签色块 (C) → 描边框 (D) → Bullet 文字 (E)
4. 如有 `footerBar`，在底部渲染蓝色横条 (F)

## 十五、QA 流程（强制执行，不可省略）

### Step 1：生成后立即截图
使用 `scripts/qa_screenshot.py`，调用 PowerPoint COM 逐页导出 PNG（1400×788）。

### Step 2：逐页视觉检查清单

| 检查项 | 说明 |
|--------|------|
| 标题折行 | 主标题超过 1 行会压住内容区，需缩短 |
| 旋转乱码 | 中文旋转后显示乱码，改用英文 |
| 元素重叠 | 文字框/形状相互遮挡 |
| 文字溢出 | 文字超出边框被裁切 |
| 对齐不齐 | 同类元素左边缘/顶部不对齐 |
| 空白卡片 | 某列/某行内容为空显得突兀 |
| 页脚碰撞 | 内容区最后一行与页码重叠 |
| 边距不足 | 元素超出 0.5" 边距 |
| 装饰线缺失 | 顶部蓝绿渐变线遗漏 |

### Step 2B：内容可讲性检查（演讲体检）

视觉 QA 之后，额外检查每页是否"能讲"：

| 检查项 | 说明 |
|--------|------|
| 标题是完整句子 | 能当一句话念出来（如"会员运营是蒙牛2026年增长核心引擎"），不是名词短语 |
| 页面有展开空间 | 不是只有 3 个关键词无处发力，每页至少有 1 个要点可以展开讲 30 秒 |
| 无纯图页 | 全图无文字的页面必须配有 `speaker_notes`，否则听讲分离 |
| 整 deck 有记忆点 | 讲完之后听众能说出 1 个最重要的结论 |

**未通过时的处理**：不是重新截图，而是回到 JSON 数据层，补充 `speaker_notes` 或调整 `desc`/`items` 内容，让页面"有话可讲"。

### Step 3：修复 → 重新生成 → 重新截图确认
**不允许仅凭代码推理判断修复成功，必须再次截图验证。**  
⚠️ **迭代上限**：修复 → 重新截图最多 **3 轮**。第 3 轮后仍有未通过项，停止迭代，输出《待确认问题清单》请哈哥人工判断。---
