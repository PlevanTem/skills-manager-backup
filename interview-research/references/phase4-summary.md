# Phase 4：逐字稿 → 访谈纪要

这是整个 Skill 最核心的阶段。

## 触发条件

用户上传或粘贴逐字稿/访谈记录，并提到"纪要/总结/整理"。

## 输入收集

1. **逐字稿**（必需）
2. **访谈大纲**（强烈建议，用于按主题组织纪要）
3. **补充资料**（可选）— 在处理逐字稿前，主动询问用户：

> 是否有以下补充资料？有的话可以提供，没有也完全没问题：
> - 会议录制文件的链接（如腾讯会议、Zoom 回放链接）
> - 受访者背景资料（如简历、个人主页、社交媒体资料）
> - 访谈时收集的截图或使用记录（如产品截图、操作录屏、工作流示意图）
> - 其他相关文档（如受访者分享的文件、项目链接等）

4. **已有纪要**（可选）— 如果已有其他受访者的纪要，确认是否需要在本篇中加入对比表

## 工作流

### 步骤 1：通读全文

建立整体理解。注意：
- 标记关键段落和高价值引用
- 识别逐字稿中模糊或可能的识别错误内容
- 如果不清晰内容较多，输出「待澄清转录内容」表格（见下方）

### 步骤 2：按主题提取

以大纲话题模块为骨架组织发现（非按时间线）。如果没有大纲，根据逐字稿内容自动识别主题并与用户确认。

### 步骤 3：生成结构化纪要

严格按以下模板框架输出。将方括号中的占位符替换为实际内容：

---

```markdown
# 访谈纪要：[受访者姓名/编号] — [公司/角色]

| 项目 | 信息 |
|------|------|
| **受访者** | 姓名（角色）｜[如有补充资料，附相关链接] |
| **人群分类** | [初始分类] + 基于访谈内容的更精准定位描述 |
| **访谈日期** | YYYY-MM-DD |
| **访谈人** | [姓名] |
| **访谈时长** | 约 X 分钟 |
| **录音/回放** | [如有链接] |
| **受访者背景** | [2-3 句完整摘要，基于逐字稿内容 + 补充资料] |

---
```

## 低质量逐字稿处理

遇到逐字稿中模糊或疑似识别错误的内容，标注 `[原文不清晰]` 而非猜测。

如果不清晰内容较多（超过 5 处），**单独输出**一份「待澄清转录内容」文件（不要附在纪要末尾），命名为 `待澄清_[受访者标识].md`，格式如下：

```markdown
# 待澄清转录内容：[受访者姓名/编号]

> 以下内容在逐字稿中不清晰或疑似识别错误，建议参照录音回放补充。补充后可重新生成相关纪要内容。

| 序号 | 时间戳（如有） | 上下文 | 不清晰内容 | 可能的含义 | 用户补充 |
|------|-------------|--------|----------|----------|---------|
```

这样纪要本身是一份随时可发布的干净文档，无需手动删除待澄清内容。

## 多语言处理

- 纪要正文语言遵循全局配置（默认中文）
- 用户原话**始终保留原始语言**，不做翻译替换
- 如原话非纪要正文语言，在原话下方附翻译（格式：`「翻译内容」`）

## 摘要版（可选）

如果用户在全局配置中选择了"同时产出摘要版"，在详细版之后额外输出：

```markdown
# 访谈摘要：[受访者姓名/编号]

**一句话摘要**：...

**核心发现**：
1. ...
2. ...
3. ...

**关键金句（3-5 条）**：
> "..." — [场景]

**业务启示**：
- ...
```

## 完成后主动询问

1. 如果有已完成的其他纪要：**"是否需要回溯更新之前的纪要，补充对比表？"**
2. **"基于本次访谈的实际情况，是否需要产出一份更新版大纲供后续访谈参考？"**（如需要，生成新文件如 `interview-guide-v2.md`，不覆盖原有大纲）

## 质量检查

- 每个核心发现是否有用户原话支撑？
- 是否区分了行为事实和态度表述？
- 是否记录了用户的变通方法（workaround）？
- 用户原话是否保留了原始语言和口语化表达？
- 分析师的解读是否与用户原话明确分开（原话在 blockquote 中，分析在正文中）？
