# 通用 3D 生成与交付

面向 Claude Code、Codex 等编码代理：将需求转成可运行、可检查、可交付的 3D 结果。既支持从零创作，也支持基于参考、资产或现有项目修改；用户只要选型时提供决策，要求制作时继续实施。不要把任何论文、模型、工具、框架或多代理流程当作默认依赖。

## 工作流程

1. **确定目标。** 识别产物及运行环境（可编辑源、模型文件、网页/游戏、图片/视频、仿真资产等）、用途、参考、风格、交互、动画、目标设备、几何精度、格式、时间及资源。检查已有项目、可用工具和用户指定方案。对不影响行动的缺项给出合理默认；只有关键缺项会改变方案或造成错误行动时才问。
2. **设计链路。** 阅读 [场景与技术选型](references/selection.md)，选择表示、生成方式、创作/运行时、输出和验证方法；现有资产或项目满足需求时优先复用。区分离线渲染、实时交互、物理仿真和二维视频，不把某一层视作整个技术栈。说明关键权衡，必要时提出备选，尊重用户既定技术约束。
3. **先做可验证的最小结果。** 阅读 [实施与验收](references/production.md) 中相关部分；确认工具、依赖、版本、可访问资源和素材授权，再搭最小场景或单一关键资产，尽早执行和查看。渐进构建几何、构图、材质、灯光、运动及交互。用户提供参考时记录可见证据和未确认部分，比较相同视角、状态和条件。
4. **迭代和核验。** 先修阻断运行、几何与功能错误，再修构图和视觉；按需求测试尺寸、碰撞、动画、性能和导入。渲染多视角或关键帧，实际打开最终目标格式/运行环境并检查；无法执行时标明原因与未知项。依靠可重复的检查，但避免为了简单任务强制建立复杂评测平台或多代理体系。
5. **交付。** 提供可用文件和源码路径、构建/运行方式、主要依赖和版本、验证证据、已知局限与未完成项。成功启动不等于视觉正确；截图好看不等于资产可编辑、可制造或仿真正确。用户只需静态图片时无需强制产出交互应用，反之亦然。

## 关键判断

- 网页 3D、游戏引擎、离线 DCC、CAD、机器人描述、shader、重建与生成模型各有不同交付物和约束，不能直接互相替代。
- 参数化代码适合精确可复现；手工或混合建模适合高艺术控制；摄影测量/辐射场适合有采集素材的重建；生成模型适合快速探索或生成候选，但需核查可访问性、费用、许可和结果可编辑性。选用取决于任务，并非一刀切。
- 转换前后检查单位、坐标系、法线、网格、材质、纹理、骨骼和动画；目标格式与接收端支持为准。渲染结果、神经场和视频不天然等于可打印、可碰撞或可编辑网格。
- 如需参考来源而非泛化流程，可选读 [3DCodeVerse 项目证据](references/3dcodeverse-stack.md)，但其术语、覆盖范围和结果不限制本指南。
